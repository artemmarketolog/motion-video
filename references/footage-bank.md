# Синхронная сборка «кадр под фразу» — рекламный ритм

> Сборка идёт в шаблоне `footage-ad`: синхрон = `"sync": true` в `creative.json` и
> `python3 build.py --plan-shows`; субтитры — [captions.md](captions.md); плашки и карточки — [inserts.md](inserts.md).
> Ниже — методика банка фаз, подписей и разбивки на показы, на которой этот режим построен.


Как собрать ролик, где кадр меняется каждые **≤3с** и показывает **ровно то, что звучит** в этот момент.
Это НЕ то, что делает обычный режим `footage-ad` (без `sync`): он подгоняет только общую длину.

**Основной путь — `"sync": true` в `creative.json`** (делает всё, что описано ниже): `python3 build.py --plan-shows`
печатает показы для разметки → размечаешь `edl` по одному кадру на показ → сборка (Шаг F).
Разделы A–E ниже — как это устроено внутри.

## Зачем (какую ошибку это чинит)

Обычный режим подгоняет ТОЛЬКО общую длину: берёт edit-list, набивает кадры по порядку и режет
из середины, сохраняя начало/конец. Кадр НЕ привязан к смыслу фразы. Итог — «героиня радуется под
словами про боль», «уведомление о деньгах не там, где про деньги», b-roll поверх ключевой фразы.
Плюс `whole`-кадры (8с) висят и добивают и ритм, и синхрон.

Для рекламы нужно два свойства: **(1)** кадр меняется каждые ≤3с; **(2)** кадр = то, что звучит.
Оба даёт метод ниже.

## Принцип

1. Банк — короткие кадры-**фазы** (по 3с, с небольшим запасом), БЕЗ `whole`.
2. Озвучку режем на **показы** — смысловые фразы ≤3с — по TTS-таймингам слов.
3. Каждый показ вручную привязываем к **конкретной фазе кадра** по `desc`.
4. `len` показа = **интервал до начала следующей фразы** (пауза включена) — кадр держится ровно
   под свою фразу, сумма = длине озвучки.
5. Монтаж — кадры ровно по `len`, без подгонки длины.

## Шаг A — банк под синхрон: короткие кадры-фазы, без whole, с запасом

Рекламный кадр ≤3с. Режем каждый 8с клип на 3 куска-фазы; `whole` НЕ используем.
- В `clips_catalog.json`: `whole=false` у ВСЕХ клипов; `best_segments` = 3 окна с запасом длины:
  **старты 0 / 2.4 / 4.5, длина ~3.5–3.8с** → `[(0,3.8),(2.4,6.2),(4.5,8.0)]`.
  Запас (3.5–3.8, а не ровно 3) нужен, чтобы кадр **покрывал показ-с-паузой** (фраза + пауза до ~3.6с);
  на экране сборка подрежет кадр под точный `len`. Старты держать близко к 0/2.5/5 — тогда при
  пере-нарезке подписи переносятся по контентному ключу (допуск 0.6с), переописывать не надо.
- `prepare_shots --max-seg 4 --zoom 1.05` (**Veo/watermark-источник**: zoom-кроп 1.05 убирает водяной знак «Veo» из правого нижнего угла — запекается в банк здесь, это ЕДИНСТВЕННОЕ место, где зум влияет на кадры; для чистого источника — 1.0). Даёт по 3 кадра на клип:
  `NN_slug__s1.mp4` (0–3.8с), `__s2` (2.4–6.2с), `__s3` (4.5–8с).
- Пример: 27 клипов → **81 кадр** по 3.5–3.8с, без звука.
- Нарезка (>1 мин) — в ФОНЕ (`run_in_background`), иначе упрётся в 2-мин лимит bash.

## Шаг B — подпись кадров субагентами ПО ФАЗАМ

Каждый `__sK` — отдельная фаза клипа, и это главное: подпись фазы даёт выбрать точный момент.
Пример (кадр 11 «уведомление о деньгах»): `__s1/__s2` — уведомление висит на экране, `__s3` — уже
уезжает. Значит «пришло 300$» ставим на `11__s1`, а не `__s3`.

- Субагенту дают клипы группами **по 3–4 клипа (= 9–12 кадров)**, он описывает каждую фазу.
- Количество: 27 клипов → **8 субагентов** (быстрая модель с vision, фон). Промпт: извлечь стоп-кадр из середины
  каждого 3с-кадра → Read (vision) → `desc` + `subjects/beat/plan/location/on_screen`; подчеркнуть,
  что `__s1/s2/s3` — фазы (начало/середина/конец), описывать что происходит именно в этой фазе.
- Слить `merge_shot_meta.py`, гейт `--check` (покрытие N/N).

## Шаг C — разбивка озвучки на показы (≤3с)

Из `scenario_voice.words.json` (тайминги слов от TTS) + текста сценария (пунктуация). Пунктуации в
words.json НЕТ — берём из `.txt`, сопоставляя слова по порядку. Жадно: набираем слова, режем показ на
границе фразы (`.,!?;:`) при длине ≥1.7с и форсируем при >2.85с; коротыши <0.8с клеим к предыдущему.
Длину показа считаем в УСКОРЕННОМ времени (÷1.15). Встроено в `footage-ad`: `python3 build.py --plan-shows`
печатает показы.
- Пример: озвучка 51.5с → **20 показов** по 2–3с.

## Шаг D — разметка показ → кадр (по desc)

Вручную, по `shots_catalog.json` (desc/beat каждой фазы): каждому показу — `NN_slug__sK`, выбирая фазу
под смысл фразы. Правила: **сосед-клип не повторять** (иначе кадр «залипнет»);
событие ставить на нужную фазу («захлопнула ноут» → `02__s2`; «пока дочка рядом» → `26__s2`, где она
поворачивается к дочке; CTA → `30__s3`, преподаватель лицом к камере).

## Шаг E — edit-list с `len` = интервал до следующей фразы

Ключевой момент, где легко ошибиться. `len[i]` считать НЕ по звучанию слов показа, а по интервалу
до следующего показа (пауза входит в кадр):
```
len[0]         = start_первого_слова[1] / 1.15                          # первый кадр ОТ НУЛЯ (ведущая пауза)
len[i]         = (start_первого_слова[i+1] − start_первого_слова[i]) / 1.15
len[последний] = (длина_ускоренной_озвучки + 0.4с) − start[последний]/1.15   # тянем до конца + запас
```
Так сумма `len` = длине озвучки + запас, видео ≥ голоса (CTA не обрезается). Если считать только по
звучанию слов (без пауз) — видео выйдет на 3–5с короче голоса, и конец обрежется. Первый кадр от нуля —
единый ноль с голосом и субтитрами. `footage-ad` в режиме `sync` делает это сам; whole в синхроне
запрещён (сыграл бы полный атом мимо тайминга); если атом банка короче слота — держится последний кадр
(но чище банк с запасом длины).

## Шаг F — сборка

```bash
cd /ABS/video-studio/projects/footage-<client>-<name>-<date>
# 1) показы для разметки edl (по одному кадру на показ); озвучка берётся та же, что пойдёт в сборку (кэш)
python3 build.py --plan-shows
# 2) в creative.json: "sync": true, "edl": [{"shot": "NN_slug__sK.mp4"}, …] — len не указывать, посчитается
python3 build.py
python3 "$S/hf.py" "$PWD" check --json
python3 "$S/mv.py" build "$PWD" -o output/master-r1.mp4 --note "первая сборка"
```

- Озвучка: `"voice": {"script": "work/script.txt", "voice": "<алиас>", "tempo": 1.15}` — новая, платная, с кэшем
  по тексту; или `{"mp3": …, "words": …, "tempo": 1.15}` — уже утверждённый дубль. Тайминги слов остаются
  сырыми, масштаб под ускорение считает сборка.
- Кадр берётся как есть; если `len` меньше длины атома — подрезается без повторного зума.
- Выдача: ссылка на мастер; Google Drive — `scripts/footage/upload_gdrive.py` в папку клиента из `clients.json`.

## Грабли (все — из первого прохода реального клиента)

- **Разметку вести под `--plan-shows`, а НЕ под отдельно сгенерённую озвучку.** ElevenLabs недетерминирован: каждая генерация даёт чуть другую длину/разбивку → другое число показов. Озвучка кэшируется по тексту, голосу и модели; размечай `edl` под показы из `build.py --plan-shows` — та же кэш-озвучка пойдёт в сборку, числа сойдутся. Разметишь под чужую озвучку → сборка честно упадёт «shows != shots» (на первом проходе так разошёлся один ролик: 20 против 19).
- **Обычный режим ≠ синхрон.** Он только про длину. Для «кадр под фразу» — `"sync": true`.
- **`len` по интервалу до след. фразы, не по звучанию** — иначе видео короче голоса, CTA обрежется.
- **Кадр-атом должен покрывать показ (до ~3.6с)** → банк с запасом 3.5–3.8, не ровно 3.
- **Исходники и банк — без звука** (`compress_media.py --no-audio`; нарезка и так `-an`). Иначе
  исходный звук клипов лезет в аудио-микс.
- **Прерванный по таймауту `compress_media` оставляет `*.compress.mp4` огрызки** — чистить перед
  каталогизацией, иначе субагенты каталогизируют мусор и число кадров «поплывёт».
- **Переименование клипов в `NN_slug` — ДО нарезки** (имена кадров банка производны от имени клипа).
  Сопоставление клип→номер банка делают субагенты-каталогизаторы по `_shot_map.md`.
