# Новый проект/клиент с нуля — повторяемый процесс подготовки кадров

> Сборка — шаблон `footage-ad` ([footage.md](footage.md)): синхрон = `"sync": true` в `creative.json` и
> `python3 build.py --plan-shows`; субтитры — [captions.md](captions.md); плашки и карточки — [inserts.md](inserts.md).


Для ЛЮБОГО нового клиента кадры свои, но процесс один и тот же. Прогнать по шагам — и банк готов к сборке креативов. `V=<motion-video>/.venv/bin/python`, `SD=<motion-video>/scripts/footage`, `cd <studio>` (по умолчанию `~/video-studio`).

## 1. Завести клиента
- Придумать **slug** (латиницей, напр. `sample-brand`) — он же имя папок `sources/shots/output/<slug>`. Один клиент × направление = свой slug (`acme-coffee`, `acme-coffee-delivery`).
- Подпапка на Google Drive (если работаете с Диском): создать вручную, folder-id — последняя часть ссылки на папку.
- **Запись в реестр** `<studio>/clients.json`: `"<slug>": {"display_name": "<Имя>", "drive_folder_id": "<id>", "tts_voice": "<голос>"}`.
  - `display_name` должен быть **уникальным**. В `creative.json` всегда указывать `"client": "<slug>"`, а не display_name.
  - Опц. `"overrides": {...}` — пер-клиентские дефолты: `zoom`, `font`, `fontsize`, `text_case`, `highlight_color`, `pos`, `seg_len`. Приоритет: `creative.json` > overrides > общий дефолт. Пример: источник без watermark → `"overrides": {"zoom": 1.0}`.
- Голос: если фирменный — `eleven.py voices --add <алиас> <voice_id>` в скилле elevenlabs-voice (единый личный реестр голосов).

## 2. Скачать клипы (Drive API, надёжнее gdown)

> Клипов ещё не существует и кадры будут генерироваться нейросетью? Тогда сначала **[footage-shot-prompts.md](footage-shot-prompts.md)** — там весь этап «до»: как спроектировать банк по драм-ролям, как писать промпты (отдельно на изображение, отдельно на анимацию), как удержать одного и того же героя во всех кадрах. пользователь генерирует по этому ТЗ и складывает клипы на Drive, дальше возвращаемся сюда.
```bash
$V $SD/download_gdrive.py --folder-id <ID_папки> --out-dir sources/<slug> [--skip-existing]
```
Переименовать в осмысленные `NN_краткое-описание.ext` (по алфавиту = дефолтный порядок), сохранить оригинальные имена в `_original_names.txt`.

## 3. Сжать исходники (не хранить тяжёлое, качество почти не теряется)
```bash
$V $SD/compress_media.py --dir sources/<slug> --no-audio   # crf23, БЕЗ звука, in-place
```
`--no-audio` — исходный звук клипов в монтаже не нужен (в ролике только озвучка + музыка), убираем сразу, иначе он лезет в аудио-микс. Сжатие 20+ клипов долгое → запускать в ФОНЕ (не в 2-мин лимит bash). Прерванный по таймауту прогон оставляет `*.compress.mp4` огрызки — удалить их перед каталогизацией, иначе субагенты опишут мусор и число кадров «поплывёт».

## 4. Каталог клипов (нейтральная опись) — СУБАГЕНТАМИ
Субагенты просматривают кадры каждого клипа и пишут `clips_catalog.json` (что на клипе, теги, лучшие куски). Разбить N клипов на группы по ~3-4, запустить параллельно. **Промпт каталогизации** (на клип):
> Каталогизируешь клипы для рекламного видео <ниша>. НЕ редактируй файлы. Для каждого клипа: ffprobe длительность; извлеки 4 кадра (0.3с/33%/66%/95%) в scratchpad; посмотри Read (vision); опиши. Верни JSON по схеме `{"clips":[{"file","duration","scene","action","emotion","motion","tags":[5-8 слов],"whole":<true если клип нельзя резать — цельная сцена>,"best_segments":[{"start","end","note"}]}]}`. **best_segments задавать с запасом по длине** (окна ≥4с, где контент позволяет) — так один банк обслужит и короткие 2с, и длинные 4с кадры (длину показа подрежем позже, без перенареза). Русский. Только JSON.

Клип, который теряет смысл в нарезке (напр. «мама забрала телефон»), помечать `"whole": true` → в банк попадёт одним кадром `__whole.mp4`. (Для рекламного ритма ≤3с whole лучше НЕ плодить — [footage-bank.md](footage-bank.md).)

**Мельче = быстрее:** по ~3 клипа на субагента (27 клипов → ~9 агентов параллельно). Имена с Drive неосмысленные? Дать субагентам карту банка `_shot_map.md` (`NN → что в кадре / герой`), пусть сопоставят каждый клип с номером (`matched_shot` в JSON). Затем **переименовать клипы в `NN_slug.mp4` ДО нарезки** (имена кадров банка производны от имени клипа), оригиналы — в `_original_names.txt`.

## 5. Нарезать банк (сжато crf23, «с запасом по длине»)
```bash
$V $SD/prepare_shots.py --catalog sources/<slug>/clips_catalog.json \
    --clips-root sources/<slug> --out-dir shots/<slug> --max-seg 4
```
Кадры-атомы нормализованы 9:16, зум против watermark, 30fps, **crf23** (лёгкие). `--max-seg` = верхняя граница длины атома; **режем с запасом (4с)** — длину ПОКАЗА потом уменьшаем per-element `len`/`--seg-len` без перенареза (см. шаг 7). Для источника без watermark добавить `--zoom 1.0`. whole — целиком. Пишет `shots_catalog.json`. Пере-нарезка переносит подписи (`desc`/структурные поля) по КОНТЕНТНОМУ ключу (source+src_start) и печатает отчёт: сколько перенесено, где смещение >0.5с (перепроверить), сколько без desc.

## 6. Подписать КАЖДЫЙ кадр — СУБАГЕНТАМИ (быстрая модель с vision)
Чтобы edit-list точно ложился под сценарий: кадр должен показывать именно то/того, о ком/чём речь. Разбить кадры банка на группы по ~9-12 (по 3-4 клипа с их фазами), запустить параллельно (пример: 81 кадр → 8 субагентов). Если кадры — фазы одного клипа (`__s1/s2/s3` = начало/середина/конец), подчеркнуть в промпте: описывать, что происходит именно в ЭТОЙ фазе — тогда под фразу подбирается точный момент (событие, реакция), см. [footage-bank.md](footage-bank.md). **Промпт описания** (на кадр):
> Подпиши каждый кадр банка для подбора под смысл фраз сценария. Папка `shots/<slug>/`, кадры: [список]. Для каждого: ffprobe длительность → извлеки кадр(ы) из середины (**для whole и кадров >3с — 2-3 кадра: начало/середина/конец**) → Read (vision) → верни JSON `{"shots": {"имя.mp4": {"desc": "…", "subjects": […], "beat": "…", "plan": "…", "location": "…", "on_screen": "…"}}}`, где:
> - **desc** — ОДНА самодостаточная фраза: кто/что в кадре (люди с приметами: пол/возраст/роль, ЯВНО — «мальчик ~11 лет», НЕ «тот же мальчик»/«та же пара»), что происходит, ключевая деталь. Без ссылок на соседние кадры.
> - **subjects** — список: кто/что (`мальчик ~11`, `мама`, `бабушка`, `преподаватель`, `руки`, `семья`, `телефон`).
> - **beat** — драм-роль под сценарий: `боль` | `решение` | `результат` | `эмоция` | `процесс` | `CTA`.
> - **plan** — `крупный` | `средний` | `общий`.
> - **location** — где (`класс`, `дом`, `кухня`, `прихожая`, `улица` …).
> - **on_screen** — что на экране устройства (`Scratch`, `ChatGPT`, `ИИ-арт`, `игра`, `соцсети`, `нет`).
> Возраст везде в едином формате (`~NN лет`). Русский, ёмко. Только JSON.

Слить фрагменты субагентов в каталог хелпером (валидирует имена и покрытие, а не ручной перенос):
```bash
$V $SD/merge_shot_meta.py --catalog shots/<slug>/shots_catalog.json frag1.json frag2.json …
$V $SD/merge_shot_meta.py --catalog shots/<slug>/shots_catalog.json --check   # гейт: desc у N/N кадров?
```
Неизвестное имя кадра → ошибка (опечатка не проходит молча). Неполное покрытие → ненулевой код + список кадров без desc.

## 7. Готово — собирать креативы
Сценарий (**сначала свериться с историей заходов — шаг 8**; утвердить, БЕЗ тире `—`, чеклист признаков ИИ из [copy.md](copy.md)) → сборка:
```bash
S=<motion-video>/scripts
$V $S/new_project.py <studio>/projects/footage-<slug>-<name>-<date> --template footage-ad --format 9:16
cd <studio>/projects/footage-<slug>-<name>-<date>
# creative.json: "client": "<slug>", "shots_dir": "<studio>/shots/<slug>", edl, voice, music, captions, inserts
$V build.py && $V $S/hf.py "$PWD" check --json && $V $S/mv.py build "$PWD" -o output/master-r1.mp4 --note "v1"
```
- `edl` подбирать по `shots_catalog` (desc/структурные поля) под смысл фраз; без `sync` длину подгонит сборка
  (лишнее убирается из середины, начало и финал сохраняются).
- **Рекламный ритм «кадр под фразу, смена ≤3с»:** `"sync": true` (`python3 build.py --plan-shows` печатает показы →
  размечаешь `edl` по кадру на показ → сборка; метод в [footage-bank.md](footage-bank.md)). Банк — короткие
  кадры-фазы без whole, источник с водяным знаком режется с `--zoom 1.05`.
- **Длина кадров**: `seg_len` (в `creative.json` или overrides клиента) — общий потолок показа (2/3/4 с);
  `"len": 2.0` в элементе `edl` переопределяет (ровный ИЛИ переменный ритм: интро по 2 с → финал по 3–4 с).
  whole всегда целиком. Кадр длиннее потолка подрежется автоматически (банк резали с запасом).
- **Голос и стиль субтитров** берутся из реестра клиента, если не заданы в `creative.json`. Новый трек —
  прописать громкость в `<studio>/music/levels.json`.

## 8. Вести историю сценариев (что заходит, что нет)
Чтобы новые сценарии писать не с нуля, а от рабочих заходов — на клиента×направление держим `sources/<slug>/scenarios-log.md` (человекочитаемый обзор; машиночитаемая шапка — YAML-frontmatter). Один файл, единый формат для любого клиента.

**Что внутри:** блок **«Инсайт направления»** (что заходит / что слабо — читать первым), **«Сводка»** (таблица: крючок 1-й секунды · показы · клики · лиды · CPL · вердикт), **карточки** по каждому сценарию (крючок, почему сработал/нет, вердикт), **«Журнал замеров»** (append-only, по датам — виден тренд). Вердикты: `★ ЛУЧШИЙ` · `работал` · `слабо` · `🧪 на тесте` · `выключен`.

**Как использовать (цикл):**
1. **Перед новым сценарием** — открыть лог, прочитать «Инсайт» и «Сводку»: брать заходы-победители, избегать слабых. (Пример из практики: острая сцена-конфликт про телефон с 1-й секунды даёт CPL $0.98; рассуждение/абстракция в начале — CPL в ~5× хуже.)
2. **Запустил на тест** — добавить сценарий в «Сводку» и карточку со статусом `🧪 на тесте` + гипотезой (какой инсайт проверяем).
3. **Пришли метрики из Meta Ads** — строка в «Журнал замеров», обновить вердикт, при необходимости пересобрать «Инсайт направления».

**Завести новому клиенту:** скопировать существующий `scenarios-log.md`, поправить frontmatter (`client/slug/direction/landing`), очистить таблицы и «Инсайт» — дальше наполнять по мере тестов. Правила ведения продублированы в конце самого файла (раздел «Легенда»).

---
**Что всегда сжимаем (crf23, качество почти без потерь):** исходники (шаг 3), кадры банка (шаг 5, SEG_ENC), итоговый ролик (subtitles.burn). Тяжёлых near-lossless файлов не держим.
