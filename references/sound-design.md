# Звуковой дизайн

Звук должен иметь ту же причину, что и картинка: пузырь появился — «поп», камера проехала — воздух,
цифра встала — мягкий удар. Звук без причины в кадре = шум. Один акцент на долю: несколько звуков
в одну точку читаются как суета (правка пользователя по 02: «слишком много звуков одновременно»).

## Повторы (урок ролика 09, пользователь 01.10.2026)

Один и тот же звук много раз подряд с жёсткой атакой бесит (20 одинаковых штрихов прорисовки за ролик).
Поэтому `sfx.py` по умолчанию делает каждое событие своим: высота ±4 %, длина ±10 %, громкость ±1,5 dB,
мягкая атака 3 мс. Для чёткого удара в событии `"attack_ms": 0`, для точного повтора `"vary": 0`
(`"vary": 0` в корне `events.json` возвращает прежний звук бит в бит). Если один пресет звучит 4+ раза
за 3 с, `sfx.py` пишет предупреждение: оставь один звук на группу действий или чередуй 2–3 пресета.
Свой синтез в `build.py` подчиняется тому же правилу: рандом тембра, мягкая атака, один звук на группу.

## Пресеты (`scripts/sfx.py`, простой и средний уровень)

`python3 sfx.py list` — все с параметрами; `sfx.py audition /tmp/demo.wav` — все подряд.

| Пресет | Когда | Громкость в `events.json` (от) |
|---|---|---|
| `tick` | счётчик, пункт списка, шаг курсора | −18…−10 dB |
| `tap`, `key` | тап по экрану, печать | −20…−12 |
| `pop` | появление пузыря/карточки | −10…−6 |
| `notify` | входящее сообщение (две мягкие ноты, без звона) | −12…−8 |
| `swipe`, `whoosh` | смена слайда, пролёт камеры (`dur`, `f0`, `f1`) | −16…−8 |
| `cloth`, `paper` | спокойная смена сцены, карточка/фото | −14…−10 |
| `soft_hit` | акцент в презентации без драмы | −12…−6 |
| `hit`, `sub` | удар/дроп в рекламе, ключевая цифра | −8…−2 |
| `air` | вдох перед ударом (`lead`: начать раньше события) | −12…−8 |
| `riser` | подводка к дропу 1–2 с | −14…−8 |
| `shimmer`, `glass` | блик по золоту/стеклу, тихо | −20…−14 |
| `click`, `relay` | механика (штифт по язычку, реле ламп) | −10…−4 |
| `shutter` | скриншот, фотоаппарат | −14…−10 |

`events.json` пишет `mvlib.Comp.sfx(t, name, gain_db, pan, lead, **params)`; `build.py` рендерит стем
`work/sfx.wav` и кладёт его в `mix.json` как `role: sfx`. `room` добавляет ранние отражения (глубина комнаты).
После сборки: `audiocheck.py master.mp4 --events events.json`: онсеты против событий (медиана ~0–6 мс, мягкая атака 3 мс).
Уровень SFX и музыки относительно голоса: [mix.md](mix.md).

## Премиум: звук из функции движения

Если движение считается физикой (колесо, пружина, маятник), звук синтезируется **из той же функции**:
моменты щелчков = моменты, когда штифт соскакивает с язычка; громкость зависит от скорости; после
главного события механика стихает и уступает место музыке. Так глаз и ухо видят одну причину.
Рабочий пример: `scripts/sfx.py` (`flap_and_ticks`), разбор в [cases/hero-object-wheel.md](cases/hero-object-wheel.md).
Такие стемы добавляются в `mix.json` отдельным треком `role: sfx`.

## Чего нет и не будет

Игровые писки, «тиньки», мультяшные boing, звон колокольчиков, лазерные «пиу». Сухо, конкретно, физично.
Вкус звука измерения не проверяют: если никто не слушал, так и пиши.
